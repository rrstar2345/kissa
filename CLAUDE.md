## Objective
Desktop trading app for stock/options: live option prices from NSE public API (default) or Fyers (user's own creds), charts with indicators and rule-based signals, and order placement through the user's `broker-proxy` (static-IP VM) fronting Dhan. **Credentials, order log and account data stay client-side** (secrets in OS keychain, everything else in SQLite).

**Strategy: harden the product with paper trading first.** The user has not set up the VPS, Dhan or Fyers, so nothing real-broker or Fyers is validated. Paper must behave like a real broker so switching later is a small change. For dev without a VPS: run `broker-proxy` locally (localhost is allowed), `proxy keygen`, enter the key under Settings > Server connection (paper orders require it, see Order gate).

Stack: Tauri v2 (Rust) + SvelteKit/Svelte 5 + Tailwind v4 + DaisyUI 5 (themes `kissa-dark`/`kissa-light`, all styling in `src/app.css`), `sqlx` 0.9 SQLite, lightweight-charts.

## What is built
All items below are tested by the user unless noted. Details are kept only where a pending roadmap item or a future change needs them; read the code for the rest.

- **Accounts** (`accounts.rs`): kinds `paper`, `dhan`, `proxy`, `fyers`. Secrets (Dhan/Fyers tokens, app secret) live in the OS keychain; the frontend never receives them. Fyers login (`components/FyersLogin.svelte`): auto (loopback redirect `http://127.0.0.1:<port>/`, default 8765, avoid browser-blocked ports like 5060/5061) or paste of the auth code; token expires daily 6:30 AM. Endpoints are `fyers.auth_url` / `fyers.validate_url`.
- **Option chain**: NSE or Fyers source, live ticks, derived OI change and Black-76 Greeks, configurable columns, click bid/ask/LTP to open the order ticket. NSE chain is empty outside market hours. Per window (`AppState.chain` keyed by window label).
- **Charts**: panels per page; instruments = indices and option strikes streamed on the chain page (ATM +-20) or by the background feed. Ticks fold into 1m bars (`bars` table), other intervals resampled on read, Fyers backfill (never run live). Indicators and auto signals as usual.
- **Signals** (`charts/rules/`, table `rulesets`): JSON `vars[]` + `entry`/`exit` condition trees. The engine is pure (`evaluate`, `conditions`, `decide`) and reused by algos and backtests. Closed candles only; Entry fires when flat, Exit only after an Entry. `/signals` page and a Signals dropdown on chart panels.
- **Orders / trading** (`trading/`): ticket, Orders/Trades/Positions pages, estimated charges (`settings.json` `trading.charges`).
  - Flow (`service/orders.rs`): validate -> server gate -> account/broker -> resolve contract -> `broker.pre_trade` -> insert -> `broker.place` -> `apply_reply`. **Every state change goes through `apply_state`** (books fills via `store::record_fill`); broker pushes arrive as `BrokerEvent` -> `apply_update`.
  - `Broker` trait (`trading/broker/mod.rs`): to add a broker, implement it in a new folder and register it in `TradingService::new`. `BrokerError.unknown` = outcome unknown (order marked UNKNOWN, resynced every 60 s).
  - Paper broker (`broker/paper/`): slippage/latency, simple margin check, day-order expiry, bracket/OCO, expiry settlement, INTRADAY square-off. Dhan via proxy: never run live.
  - Exit / Exit All (`service/exit.rs`): cancels the contract's open orders, then LIMIT at LTP +- `trading.exit_buffer_ticks`.
  - Order gate (`trading/server.rs`): `place`/`modify` need the proxy to authenticate the client; cancel is not gated.
- **Settings page**: server connection (URL, port, API key in keychain) and a `settings.json` editor. Only the `server` section applies live (Roadmap #20).
- **Risk controls** (`trading/risk.rs`, `service/risk.rs`, tables `risk_limits`, `risk_halts`): per-account limits, daily-loss monitor every 5 s, kill switch (account id `*`). **Orders that only reduce a position always pass**, so Exit, brackets and square-off are never blocked. Algos call `halt_reason(account_id)`. Event `risk-update`.
- **Alerts** (`alerts/`, table `alert_outbox`): `AlertService::notify(Alert{kind,key,title,body})` -> toggle filter -> de-dup per `kind:key` -> Telegram / SMTP delivery with retries -> history. To add an event: add a `Kind` variant (and to `Kind::EVENTS`), then call `notify`. Token expiry reminders are estimates (saved time + `fyersTokenHours`/`dhanTokenHours`). Not done: plain signal alerts (no orders), a "Detect chat ID" button.
- **Trade copier** (`trading/copier.rs`, `service/copier.rs`, table `copy_links`): one master, N children, replicated on placement through `place_inner`. `copier_lock` serialises `place`, follow tasks and exits. Child accounts should be used only for copying. Event `copier-update`.
- **Algo trading** (`algo/`, tables `algos`, `algo_state`, `algo_journal`): option algos on one saved signal; each CE/PE leg is judged on its own option bars; runner every 5 s; one capital pool per account; paper brackets or runner-watched SL/target for Dhan; `allowLive` needed for Dhan. Every decision goes to `algo_journal` (5000 rows / 60 days) and key events go out as `Kind::Algo` alerts. Needs the app running; BUY only; no stock algos. Option bars come from `trading/feed.rs` `Recording` (no live backfill). JSON share format `{kissaAlgo:1, algo, signal}`. Event `algo-update`.
- **Backtesting** (`backtest/mod.rs`, command `run_backtest`): one saved signal on one instrument over stored bars; fills at the next bar's open; long only. Not done: backtesting a saved algo, shorting, saved runs.
- **Dashboard** (`routes/+page.svelte`, `trading/period.rs`, command `get_performance`): Daily / Monthly / Yearly views, calendar heat map, diary. Each fill's realised P&L and charges belong to the IST hour/day/month of the fill; a trade = round trip (counts when it closes); ROI = net / entry premium; open positions are not included. `period.rs` is where trade / fill aggregation lives (CSV export, #18, should reuse it).
- **Top bar P&L and positions dock**: `components/TopBarPnl.svelte` (net today across accounts, same maths as the Dashboard) and `components/PositionsDock.svelte` (Option Chain and Charts). Both use `getDashboard(null)` + `livePosition` and refetch on `trading.version`. Held contracts are always recorded as bars (`Recorder::set_pinned`).
- **Multiple app windows** (`popout.rs`, `lib/windowing.ts`): any page can open in its own window (`pop-1`..`pop-8`), one process and backend, per-window JS stores fed by the same events. `isPopout` hides the sidebar. Per-window settings use `getScoped`/`setScoped` (`key@pop-N`); `data.source` and `ui.theme` are global. Open pop-outs are saved in `windows.open` and restored. `capabilities/default.json` covers `main` and `pop-*` (matters for the CSP, #21). Not done: dock back, named workspaces, query strings in pop-out routes.
- **Event-driven UI**: no timers wake the backend while the market is quiet. `LtpStore::set` notifies the `quotes` emitter (50 ms coalesce); `index-tick`, `bar-update` coalesce the same way. Frontend: `lib/timers.ts` `every(fn, ms)` skips while `document.hidden`; use it for page polls. Events: `quotes`, `bar-update`, `chain-snapshot`, `order-update`, `broker-status`, `index-tick`, `risk-update`, `alert-update`, `copier-update`, `algo-update`, `market-status`. `KISSA_EMIT_STATS=1` logs emits per second (`emit_stats::count("event")` at emit sites; add it to new emitters). The chain engine still ticks every 150 ms while a chain is open.
- **Fyers data socket** (`market/fyers_socket/`): one shared HSM binary socket (`fyers.socket_url`) for the Fyers chain, the background feed and the header indices (`bridge.rs`, same `IndexSink` as the NSE stream, NSE index names). Consumers take a `Lease` and read `hub.subscribe()`. The supervisor connects only while the data source is Fyers, a lease wants topics, and the Fyers status allows polling. REST chain call seeds the chain and refreshes every `fyers.chain_refresh_secs`; if the socket is down 20 s the chain falls back to REST. `fyers.use_socket = false` keeps REST only. Settings: `use_socket`, `socket_url`, `symbol_token_url`, `max_symbols` (100 Standard / 5000 Prime), `chain_refresh_secs`. `proto.rs` (pure, tested) and `topics.rs` (index topics from the SDK `map.json` names). `KISSA_FYERS_DEBUG=1` logs frame bytes. Hub accessors `is_connected`, `last_error`, `last_tick_age_secs` feed the header indicator. **Unverified against live Fyers:** the symbol-token `Authorization` format, exact index topic names, the auth `source` string ("kissa"), whether chain items carry `fyToken`, ack and ping behaviour.
- **Market status and data source (Roadmap #14 done; tested by the user)**: only the selected source is polled, streamed and shown.
  - `DataSource` (`nse` | `fyers`, setting `data.source`) is cached in `MarketStatusService`: loaded at startup, updated by the `set_setting` command (`set_source`). Read it with `state.market_status.source()` instead of the database. The unselected source reads `Reason::NotUsed` and makes no calls; a newly selected source gets a fresh poll at once. `trading/feed.rs` restarts its feeds when the source changes and never falls back to NSE when Fyers is selected.
  - `market/status.rs` polls NSE `/api/marketStatus` (Capital Market row; F&O follows) or Fyers `/data/marketStatus` (NSE 10, derivatives 11, NORMAL row). No calls outside the weekday 08:30-16:00 IST window; every 5 min while stable, 30 s around pre-open (08:55-09:20) and the close, none after the day's close. `guard_hours`: before 09:00 a reported Open/Pre-open shows as Closed, and 09:00-09:15 Open shows as Pre-open (the raw source text stays in the badge tooltip).
  - `SessionState` (`market_clock.rs`) is the **NSE** session only and is always Idle when Fyers is selected (`nse_enabled`): indices stream through pre-open, option streams only when Open, nothing connects while Closed (the NSE index stream makes up to 3 price-seed polls), unknown status falls back to the clock rules, streams that connect without a tick back off to 5 min. The Fyers chain page, price feed and socket use the Fyers status directly (one REST fetch when closed).
  - Header (`+layout.svelte`): one badge for the selected source (`MarketStatus.exchange`) and a feed indicator (`live`, `feed`, `feedDetail` from `commands::build_market_status`). Live = the selected source's index feed (NSE `indices` stream or Fyers socket) delivered a tick within 60 s while the exchange is Open (with an unknown status the clock decides, 09:15-15:30 weekdays); otherwise Pre-open, Closed, No ticks, Connecting, Error or Checking. The push task emits only when `change_key` changes (exchange state, source, live, feed text, stream state; tick counters and clock are ignored). `market.svelte.ts` keeps the IST clock running locally from `nowMs`.
  - Known gaps: pre-open status strings for NSE and Fyers segment 11 are unverified; special sessions outside 08:30-16:00 (Muhurat) are not covered; the header indices are empty on Fyers while the market is closed (Roadmap #15); NSE's server-time sync (`refresh_if_stale`, one small GET per 15 min) still runs when Fyers is selected. Holiday-master fetch/parse (`fetch_holidays`, `is_trading_holiday`) exists but is unused (`allow(dead_code)`).

## Notes relevant to the backlog
- **broker-proxy contract**: REST + one WSS per client. Header `X-API-Key`; `POST /v1/sessions` (`{broker:"dhan",credentials:{clientId,accessToken}}` or `{broker:"paper"}`) returns `sessionId`, then also send `X-Session-Id`. Endpoints: `POST/PUT/DELETE /v1/orders[/{id}]`, `POST /v1/orders/slicing`, `GET /v1/orders`, `/v1/orders/{id}`, `/v1/orders/external/{correlationId}`, `GET /v1/trades`, `GET /v1/ws?since=N` (events `order_update`, `feed_status`, `session`, per-session `seq` with replay and `gap`). Rules: only LIMIT and STOP_LOSS with positive `price` (no MARKET), strict JSON, idempotency via `correlationId` (`409 outcome_unknown` = check `/orders/external/{id}` first). Server persists nothing, so **the client is the system of record**. One session per Dhan account; a proxy restart drops sessions (reopen and resync).
- Paper margin is a rough estimate; positions are keyed by account + instrument + product (no INTRADAY->MARGIN conversion).
- An order left `UNKNOWN` after retries is resolved only by the 60 s order-book resync. Dhan partial fills (cumulative-quantity deltas) are unverified. `save_account` does not explicitly drop a cached Dhan connection.
- Unverified against live systems: Fyers option-chain URL (`https://api-t1.fyers.in/data/options-chain-v3`, from memory), Fyers history URL/option symbol formats, Dhan CSV columns/date format, NSE OI change (derived from first OI seen unless NSE sends it). Fyers tokens expire daily (re-run Log in each trading day).
- Charges rates and lot sizes (NIFTY 65, BANKNIFTY 30, FINNIFTY 60, MIDCPNIFTY 120, NIFTYNXT50 25) and strike steps (50 NIFTY/FINNIFTY, 100 BANKNIFTY/NIFTYNXT50, 25 MIDCPNIFTY) are estimates as of Nov 2026; verify.
- Sandbox cannot reach nseindia.com or Fyers; prefer unit tests with fixtures (the user runs `cargo test --lib`). SQLx 0.9: `format!`-built SQL must be wrapped in `sqlx::AssertSqlSafe(...)`.
