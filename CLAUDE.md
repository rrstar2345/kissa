## Objective
Desktop trading app for stock/options: live option prices from NSE public API (default) or Fyers (user's own creds), charts with indicators and rule-based signals, and order placement through the user's `broker-proxy` (static-IP VM) fronting Dhan. **Credentials, order log and account data stay client-side** (secrets in OS keychain, everything else in SQLite).

**Strategy: harden the product with paper trading first.** The user has not set up the VPS, Dhan or Fyers, so nothing real-broker or Fyers is validated. Paper must behave like a real broker so switching later is a small change. For dev without a VPS: run `broker-proxy` locally (localhost is allowed), `proxy keygen`, enter the key under Settings > Server connection (paper orders require it, see Order gate).

Stack: Tauri v2 (Rust) + SvelteKit/Svelte 5 + Tailwind v4 + DaisyUI 5 (themes `kissa-dark`/`kissa-light`, all styling in `src/app.css`), `sqlx` 0.9 SQLite, lightweight-charts.

## What is built
- **Accounts**: kinds `paper` (startingCapital, brokeragePerOrder), `dhan` (clientId, proxyId, accessToken secret), `proxy`, `fyers` (appId, accessToken secret). Frontend never receives secrets.
- **Option chain**: NSE or Fyers source, live ticks, derived OI change and Black-76 Greeks, configurable columns, click bid/ask/LTP to open the order ticket. NSE chain is empty outside market hours.
- **Charts**: multiple panels per page, instruments = indices and option strikes streamed on the chain page (ATM +-20). Ticks fold into 1m bars (`bars` table), other intervals resampled on read, daily rollup, Fyers backfill (never run live). Indicators: SMA, EMA, RSI, MACD, Bollinger, VWAP, Supertrend, plus auto signals (MA cross, RSI 30/70, MACD, BB, Supertrend flip).
- **Signals (configurable rules, Roadmap #1 done)**: `/signals` screen with editor (left) and live chart preview (right). Every chart panel has a Signals dropdown to apply saved rulesets to any instrument/interval.
  - Ruleset JSON in SQLite table `rulesets`: `vars[]` (rsi, ema, sma, macd, bb, atr, vwap, supertrend, formula; `src` = price source or an earlier var for chaining; `output` picks macd/bb/supertrend line; `plot` flag), `entry` (BUY) and `exit` (SELL) condition trees (`and`/`or` groups of `left op right`; ops `crosses_above crosses_below > >= < <= = <>`; operands = price source, var id or number).
  - Semantics: closed candles only; Entry fires when flat, Exit only after an Entry; with no Exit conditions Entry is ungated.
  - Code: `charts/rules/{mod.rs (model + validate), eval.rs (`evaluate(&Ruleset, &[Bar], closed)` returns lines + signals), store.rs}`; commands `list_rulesets, save_ruleset, delete_ruleset, validate_ruleset`; `get_chart` takes `rulesets` ids and an unsaved `draft`. Frontend `routes/signals`, `components/RulesetEditor.svelte`. **The engine is pure; reused by algos and backtests (`conditions`); alerts on plain signals can still reuse `decide`.**
- **Orders / trading** (`trading/`): order ticket, Orders/Trades/Positions pages, Dashboard (live P&L) and trader's diary with estimated charges (rates in `settings.json` `trading.charges`).
  - **Order flow** (`service/orders.rs`): validate -> server gate -> account/broker -> resolve contract -> `broker.pre_trade` -> insert -> `broker.place` -> `apply_reply`. All state changes go through `apply_state` (books fills via `store::record_fill`). Broker pushes (fills, WSS, resync) arrive as `BrokerEvent` and go through `apply_update`.
  - **Broker trait** (`trading/broker/mod.rs`, `async-trait`): `kind, needs_instrument_ids, pre_trade, place, modify, cancel, brokerage, connect, sync, forget, watched_contracts`. Registered in `TradingService::new`. To add a broker: new folder, implement trait, register. `BrokerError.unknown` = outcome unknown (order marked UNKNOWN, resynced).
  - **Paper broker** (`broker/paper/`): matching with slippage/latency, margin/funds check (simple estimate), day-order expiry, bracket/OCO (`PlaceOrderInput.bracket`, paper only), expiry settlement (`service/settle.rs`), INTRADAY auto square-off (`service/squareoff.rs`).
  - **Dhan via proxy**: `securityId` from Dhan instrument CSV (table `scrip`). **Never run live.**
  - **Exit / Exit All** (`service/exit.rs`): cancels the contract's open orders, then LIMIT at LTP +- `trading.exit_buffer_ticks`.
  - **Order gate** (`trading/server.rs`): `place`/`modify` require the proxy to authenticate the client (cached `paper` session re-validated per call). Cancel is not gated.
- **Settings page**: server connection (URL, port, API key in keychain) and a `settings.json` editor. Only the `server` section applies live; everything else needs a restart. `trading.paper {enforce_margin, short_margin_pct, slippage_ticks, latency_ms, auto_square_off, square_off_time}`.
- **Risk controls (Roadmap #2 done; Rust not yet built/tested by the user at time of writing)**: `/risk` page (per-account limits) and a kill switch button in the header.
  - Limits per account in SQLite `risk_limits` (JSON `RiskLimits`): `enabled` master switch, `maxLotsPerOrder`, `maxOpenPositions` (counts contracts held or with a resting entry order), `maxDailyLoss` (rupees), `squareOffOnBreach`, trading window (`windowEnabled/Start/End`, IST HH:MM, start inclusive, end exclusive). 0 = limit off. Halts in `risk_halts` (account id `*` = global kill switch).
  - **Check** (`TradingService::check_risk`, called in `place` after contract resolution, before insert): kill switch, active halt, then the limits. **Orders that only reduce a position (opposite side, qty <= held) always pass**, so Exit, Exit All, brackets and square-off are never blocked. Bracket legs and settlement bypass `place`.
  - **Daily loss monitor** (`enforce_risk`, every 5 s in the sweeper): net P&L today (realised + unrealised - charges, same as the dashboard) <= -`maxDailyLoss` raises a `daily_loss` halt for the IST day, cancels resting entry orders (not stop/target legs) and, if `squareOffOnBreach`, calls `exit_all`. "Resume today" sets `released`; the breach is not raised again that day. The kill switch (`set_kill_switch(on, flatten)`) persists until released and optionally flattens.
  - **For algos**: call `TradingService::halt_reason(account_id)` (kill switch or daily-loss halt); disarm on `Some`. `check_risk` already covers their orders.
  - Code: `trading/risk.rs` (limits, pure `check`, `is_reducing`, store, unit tests), `trading/service/risk.rs` (service wiring); commands `get_risk, save_risk_limits, set_kill_switch, resume_account`; event `risk-update`. Frontend `routes/risk`, `components/KillSwitch.svelte`, `trading.riskVersion`.
- **Alerts (Roadmap #3 done; Rust not yet built/tested by the user at time of writing, Telegram confirmed working)**: `/alerts` page (channels, event toggles, options, history).
  - Channels: Telegram (bot token in keychain, chat ids; Bot API cannot message by phone number) and SMTP email via `lettre` (password in keychain; `starttls` | `tls` | `none` for localhost only). Secrets live under keychain account id `alerts` (`telegramToken`, `smtpPassword`). Non-secret config is JSON in `app_settings` key `alerts.config`.
  - **Pipeline** (`alerts/mod.rs`): anything calls `AlertService::notify(Alert{kind,key,title,body})` (non-blocking) -> worker drops events switched off -> suppresses the same `kind:key` inside `dedupeSecs` (default 60) -> delivers per target (each Telegram chat and the email are separate targets) with 3 attempts, backoff 5 s then 20 s, retrying only failed targets -> records in table `alert_outbox` (status `sending|sent|partial|failed|suppressed|skipped`; 2000 rows / 30 days kept). Test button sends once, no retries, bypasses toggles and de-dup. Event `alert-update`.
  - **Events** (`Kind` in `alerts/mod.rs`; to add one: add a variant to `Kind` and `Kind::EVENTS`, then call `notify`): `fill`, `rejection`, `risk`, `connection`, `token_expiry`, `daily_summary`, `copier`. Messages and schedules are in `trading/service/alerts.rs`. Hooks: `apply_state` (fills, REJECTED transitions), `place` (immediate REJECTED), `halt_account` and `set_kill_switch` (risk; unique key so never de-duplicated), `emit_status` (connection: only the first loss and the recovery are reported, tracked per account in the worker), sweeper minute tick `alerts_tick` (daily summary once per IST weekday after `summaryTime` and only if there was activity, marker `alerts.summary_last`; token reminders).
  - **Token expiry is an estimate**: `accounts::save` stores `token_saved:{id}` when an accessToken is saved; expiry = saved + `fyersTokenHours`/`dhanTokenHours` (default 24). Stages `soon` (within `tokenWarnHours`) and `expired` are sent once per saved token (marker `token_notified:{id}`). Tokens saved before this feature have no timestamp and get no reminder.
  - **For algos / copier**: add kinds (e.g. `algo`; `copier` exists) and call `notify` from `TradingService` (`self.alerts`). `Kind::Algo` now exists (used by algos). Plain signal alerts (no orders) are still not done: they would reuse `rules::eval::decide` on bar close.
  - Code: `alerts/{mod.rs (service, kinds, worker), config.rs (config + validation), channels.rs (telegram, email), store.rs (history)}`, `trading/service/alerts.rs`; commands `get_alert_settings, save_alert_settings, test_alert, list_alert_history, clear_alert_history`. Frontend `routes/alerts`, `trading.alertVersion`.
  - Idea not done: a "Detect chat ID" button (calls bot `getUpdates` after the user messages the bot) to avoid looking up chat ids by hand.
- **Trade copier (Roadmap #4 done; tested by the user)**: `/copier` page (master, children with factor / rounding / min 1 lot / on-off, recent copies).
  - One master account, N children (paper or Dhan). Config JSON in `app_settings` key `copier.config`; links in table `copy_links` (master order -> child order, lots, status `placed|skipped|failed`, message).
  - **Replicate on placement** (user's choice, not on fill): `TradingService::place` = `copy_job` (reads config and the master's position *before* the order: intent Open / Reduce / full exit) -> `place_inner` (the old `place` body) -> `spawn_copy` unless the master order was REJECTED (UNKNOWN still copies). Children are placed through `place_inner`, so server gate, risk checks and broker rules apply and a copy is never re-copied. Children run concurrently in a background task.
  - **Scaling** (`copier::plan_lots`, pure, unit-tested): child lots = master lots x factor, Down/Nearest/Up, below 1 lot -> 1 if `minOneLot` else skipped. Orders that only reduce the master are capped at what the child holds (never opens a position the master did not); a full master exit closes the child's whole position and first cancels the child's open orders in that contract (like Exit does).
  - **Follow** (`copier_follow`, hooked in `after_state`): master order CANCELLED/EXPIRED/REJECTED -> unfilled child orders cancelled; master price/trigger changed while open -> child orders modified (not if the child is part-filled). Roles other than plain/ENTRY (stop/target legs, settlement) are ignored.
  - **Failures**: one child failing never stops the others; recorded in `copy_links` and alerted with `Kind::Copier` (a child order REJECTED by the broker only gets the existing Rejection alert).
  - **Concurrency**: `copier_lock` (`Arc<Mutex>`) is taken by `place` (owned guard) from before the master order until its copies are placed, and by follow tasks. `exit_one` waits on it and re-reads the live position, so Exit all on master + children cannot exit a child twice (this happened before the fix).
  - **Paper funds fix**: orders that only close exposure (requirement 0) always pass `check_funds`, even when the account is over-committed.
  - Not copied: the master's stop-loss/target legs and expiry settlement. A paper child gets the master's bracket on its own entry copy; a Dhan child does not (link note says so). Child accounts should be used only for copying: a full exit on the master closes the child's whole position in that contract, including anything the child traded itself. Exit / square-off / kill-switch flatten on the master are copied too (children already flat just skip).
  - Code: `trading/copier.rs` (config, scaling, links), `trading/service/copier.rs` (wiring); commands `get_copier, save_copier`; event `copier-update`. Frontend `routes/copier`, `trading.copierVersion`.
- **Algo trading (Roadmap #5 done; tested by the user)**: `/algos` page (form editor or JSON view on the left; Status, open legs and decision journal on the right; Arm/Disarm).
  - **Model** (`algo/mod.rs`, JSON in SQLite `algos`, `ruleset_id` column): `signalId` (one saved signal; a signal has many algos), `instrument {type:"option", underlying, expiry: current|next|next1|next2|next3, strikeOffset (ATM = 0, +n above, -n below, max 20), side: ce|pe|both}`, `interval` (minutes, e.g. `5m`), `action {product, capital, bufferTicks, stopLossPct, targetPct}`, `accounts[]` (many algos <-> many accounts), `copier` (algo-level switch), `allowLive`. Names are unique. Only options are supported: `type` is kept so stocks can be added later (the UI shows Stock disabled).
  - **Signal link**: signals are loaded by id on every evaluation, so editing a signal changes every algo using it. `rules::store::delete` refuses while an algo uses the signal (lists the algo names).
  - **Run loop** (`algo/runner.rs`, every 5 s, armed algos plus disarmed ones still holding a leg): **each option leg is judged on its own bars** (per-leg signals, changed after Roadmap #5 first shipped, which evaluated the underlying and opened both legs together). Once per newly closed bar (`last_closed_bucket`, session-aligned like stored bars; the first look after arming only records the baseline bucket), for each leg in the order CE then PE: a **held** leg cancels its unfilled entry and checks Exit on its own option bars (`eval::decide(.., in_pos = true)`), also for a leg whose side was removed from the algo later; a **flat** leg (armed only, side selected) takes the underlying's last closed bar close as spot, strike = ATM +- offset (`target_strike`), and checks Entry on that strike's bars. A leg's strike is fixed until that leg closes. `ce`/`pe` watch one leg, `both` watches both independently (a PE signal can come while the CE is open). A bar counts only if it exists for the closed bucket (no trades = no bar = no signal), and the option needs `warmup_bars(rs)` closed bars (sum of variable lookbacks + 2; journaled once as 'waiting for history'). Entry: BUY LIMIT at LTP + `bufferTicks`; unfilled entry orders are cancelled at the next bar. `sync_legs` drops legs whose position is closed (state in `algo_state`, targeted UPDATEs); the algo is flat when no leg is left.
  - **Capital is one pool per account** (no split between legs; `Leg.cost` = entry price x lot size x lots): lots = `floor(free / one-lot cost)` with `free = capital - sum(cost of that account's open legs)` (`free_capital`). The first leg to signal can use everything; a later leg with less than one lot free is journaled `Insufficient funds on <account>: ...` and skipped. Legs saved before this change have `cost` 0.
  - **Option bar recording** (needed for per-leg signals): the Option Chain page recorded ATM +- `charts.persist_strikes_each_side` only while open; `trading/feed.rs` (`Recording`) now records the same window for every target the background feed streams (armed algos publish theirs via `set_algo_watch`), NSE and Fyers. No live backfill: a new strike/expiry needs about `warmup_bars` x interval of recording before it can signal; arm before the open for best results. A strike that was never inside the window has no bars.
  - **Stop-loss / target**: paper accounts get bracket orders (`PlaceOrderInput.bracket`); Dhan accounts have the runner watch the price (needs the app running).
  - **Accounts and copier** (`algo::select_accounts`, pure, unit-tested): algo copier ON + copier set-up enabled + its master selected in the algo -> only the master places orders (copier replicates to its active children) and selected children are ignored (journaled). Otherwise every selected account places its own orders. Algo copier OFF -> orders are never replicated, even from a master: `TradingService::place_algo(input, propagate)` uses `place_inner` (no `spawn_copy`) and `algo_close` / `exit_one_with(.., propagate)` do the same for exits.
  - **Safety**: arming needs a valid signal, at least one account, `halt_reason` clear, and `allowLive` for any Dhan account (confirm dialog). The runner disarms on the kill switch or a daily-loss halt (alert + journal). Orders go through the normal flow, so the server gate and `check_risk` apply. `allowLive` is never exported.
  - **Prices / expiries**: entries need a live option price (age <= 120 s). The runner publishes the (symbol, expiry) pairs it needs through `TradingService::set_algo_watch`, merged into `watched_contracts()`, so the feed prices them. Expiries come from the Dhan `scrip` table, topped up from NSE `fetch_expiries` (cached per IST day). Strike steps (`strike_step`: 50 NIFTY/FINNIFTY, 100 BANKNIFTY/NIFTYNXT50, 25 MIDCPNIFTY) are estimates, verify.
  - **Journal and alerts**: every decision goes to `algo_journal` (kept 5000 rows / 60 days; kinds armed, disarmed, signal, entry, exit, skip, error, info). Entries, exits, failures and auto-disarm also go out as `Kind::Algo` alerts.
  - **JSON share**: `{kissaAlgo:1, algo:{name, instrument, interval, action, copier}, signal:{name, vars, entry, exit}}`. No accounts, ids or `allowLive`. On import, a signal with the same name is reused (you are told if its rules differ); an unknown one is created on save.
  - Limitations: the app must stay running (no headless mode); no stock algos; BUY only (no option writing); one signal per algo, one position per leg (CE, PE).
  - Code: `algo/{mod.rs (model, validation, pure maths + tests), store.rs, service.rs, runner.rs}`, `trading/service/algo.rs`; commands `list_algos, save_algo, delete_algo, set_algo_armed, validate_algo, list_algo_journal, clear_algo_journal`; event `algo-update`. Frontend `routes/algos`, `components/AlgoEditor.svelte`, `trading.algoVersion`.
- **Backtesting (Roadmap #6 done; tested by the user)**: `/backtest` page (form on the left; summary cards, equity curve and trade table on the right; last form saved in `app_settings` key `backtest.form`).
  - Runs **one saved signal on one instrument** (index or option key) over stored bars (`chart_bars`, latest 20,000, resampled), optional From/To IST dates (bars before From only warm up indicators). Stored bars only: option strikes never streamed have no data; the report warns about intra-session gaps (> 3 bars) and runs under 5 sessions.
  - **Simulation** (`backtest/mod.rs`, pure `simulate` + `summarize`, unit-tested; `run` does the I/O): long only, one position; conditions on a closed bar, fill at the **next bar's open**; stop-loss/target % via `algo::bracket_levels`, checked from the entry bar on (stop fills at trigger or open if gapped, target at price or open if gapped up, both in one bar = stop); adverse slippage in 0.05 ticks on entries and stop/signal exits; minute intervals are intraday (closed at the day's last bar, no signal carried over) unless `carryOvernight`, `Day` bars always carry; sizing = fixed lots or `lots_for_capital` (skipped if capital buys no lot); charges via `trading::charges::compute` + Dhan brokerage (flat from settings or an override, capped at % of turnover). Lot size 0 = auto (scrip table, then `fallback_lot_sizes`, index = 1 so P&L is in points).
  - Uses `rules::eval::conditions(rs, bars)` (new: per-bar Entry/Exit truth) instead of `evaluate`, because the backtest owns the position state (SL/target exits would desync `evaluate`'s own gating).
  - Stats: trades, win rate, gross/net P&L, charges, profit factor, expectancy, avg win/loss, best/worst, max drawdown (rupees and % of peak equity when a starting capital is given), longest losing streak, avg bars held, return %, closed-trade equity curve.
  - Code: `backtest/mod.rs`; command `run_backtest`. Frontend `routes/backtest`.
  - Not done: backtesting a saved *algo* (strike selection, bar data of the option legs, both legs for `both`); shorting; per-trade chart markers; saving/comparing runs.

  - Frontend: `lib/timers.ts` `every(fn, ms)` is `setInterval` that skips while `document.hidden`; use it for any page poll. `quotes.nowSecs` ticks every 5 s (freshness limit is 120 s). Remaining page polls (5-30 s) are safety nets next to events; risk page's 5 s poll feeds live P&L.
  - Not changed: the chain engine ticker (150 ms, `chain/runner.rs`) still runs while a chain is open; making it event-driven needs a spot-price wake-up.
  - Debug: `KISSA_EMIT_STATS=1` logs emits per second per event every 10 s (`emit_stats.rs`, `emit_stats::count("event")` at emit sites; add it to new emitters).
- **Real-time UI**: `quotes` event (event-driven, 50 ms coalesce), `bar-update`, `chain-snapshot`, `order-update`, `broker-status`, `index-tick`, `risk-update`, `alert-update`, `copier-update`, `algo-update`, `market-status`.
- **Market status per source. (Bug fix done)** 
  - `market/status.rs` polls NSE `/api/marketStatus` (Capital Market row; F&O follows it) and Fyers `/data/marketStatus` (NSE 10, equity derivatives 11, NORMAL row; only when Fyers is the data source).
