## Status
**The roadmap (#1-#26) is complete for this release; the next batch (#27-#31; #27 done) is under "Roadmap (next)".** Everything below is built and tested by the user, except the items listed under "Unverified". Strategy so far: harden with **paper trading**; the VPS, Dhan and Fyers have never been run live. Paper must behave like a real broker so switching later is a small change. For dev without a VPS: run `broker-proxy` locally (localhost allowed), `proxy keygen`, enter the key under Settings > Server connection (paper orders need it, see Order gate).

Product: desktop app for stock/options trading: live option prices from NSE public API (default) or Fyers (user's creds), charts with indicators and rule-based signals, backtests, algos, alerts, and orders through the user's `broker-proxy` (static-IP VM) fronting Dhan. **Credentials, orders and account data stay client-side** (secrets in OS keychain or encrypted file, the rest in SQLite/DuckDB).

Stack: Tauri v2 (Rust) + SvelteKit/Svelte 5 + Tailwind v4 + DaisyUI 5 (themes `kissa-dark`/`kissa-light`, all styling in `src/app.css`), `sqlx` 0.9 SQLite, `duckdb` crate (bars only), lightweight-charts. Rust 1.94+ (SQLx 0.9). `cargo test --lib` is the test suite (pure logic is covered; sandbox cannot reach NSE/Fyers, so prefer fixtures).

## Architecture (what to know before changing things)
- **State**: `AppState` (`state.rs`): `config` (startup snapshot) vs `live` (`LiveConfig`, settings that apply immediately: `trading.*` except `request_timeout_secs`, `risk_free_rate`, `server`; read with `live.get()` at the moment of use). Other sections are restart-only (`get_restart_pending` lists them). Edits to `settings.json` outside the app apply at restart.
- **Storage**: `kissa.db` (SQLite: orders, trades, accounts, risk, audit, algos, alerts, settings) and `bars.duckdb` (chart bars only, `charts/duck.rs` `BarStore`, every call via `BarStore.run(|conn| ..)` on `spawn_blocking` with owned data). DuckDB gotchas: integer `/` is float division (use `//`), `GREATEST`/`LEAST`, no partial indexes, `ts` is `BIGINT`, one read-write process per file. `charts/migrate.rs` moved old SQLite bars once (backup `kissa.pre-duckdb.bak.db`). `bundled` DuckDB needs a C++ toolchain (slow first build). SQLx 0.9: `format!`-built SQL needs `sqlx::AssertSqlSafe(...)`.
- **Accounts** (`accounts.rs`): kinds `paper`, `dhan`, `proxy`, `fyers`. Secrets via `secrets.rs` (`get`/`set`/`delete`): OS keychain, or `secrets.enc` (ChaCha20-Poly1305, Argon2id from `KISSA_PASSPHRASE`) when `KISSA_SECRETS=file` or the keychain fails headless. The frontend never receives secrets.
- **Orders** (`trading/service/orders.rs`): validate -> server gate -> account/broker -> resolve contract -> `broker.pre_trade` -> insert -> `broker.place` -> `apply_reply`. Every state change goes through `apply_state` (books fills via `store::record_fill`); broker pushes arrive as `BrokerEvent` -> `apply_update`. To add a broker: implement the `Broker` trait in `trading/broker/<name>/` and register in `TradingService::new`. `BrokerError.unknown` = outcome unknown (order marked UNKNOWN, resynced every 60 s). Paper broker: slippage/latency, simple margin, bracket/OCO, day expiry, settlement, INTRADAY square-off. Exit / Exit All (`service/exit.rs`): cancel the contract's open orders, then LIMIT at LTP +- `trading.exit_buffer_ticks`. **Order gate** (`trading/server.rs`): `place`/`modify` need the proxy to authenticate the client; cancel is not gated.
- **Risk** (`trading/risk.rs`, `service/risk.rs`): per-account limits, daily-loss monitor every 5 s, kill switch (account id `*`). Orders that only reduce a position always pass.
- **Audit** (`audit/`): `audit::record(Entry::new(Category, "action", "summary").account(id).subject(ref).detail(json!{..}))` from anywhere; actor (`user|system|algo|copier|broker|telegram`) from task-local `audit::scope(Actor, fut)` (spawned tasks do not inherit it). Never log secrets (detail keys containing token/secret/password/apikey are masked). Retention 90 days / 200k rows.
- **Alerts** (`alerts/`): `AlertService::notify(Alert{kind,key,title,body,fields,icon,buttons})` -> toggle filter -> de-dup per `kind:key` -> Telegram / SMTP with retries -> history (`alert_outbox`). New event = new `Kind` (and in `Kind::EVENTS`) + a `notify` call. `render.rs` turns one `Card` into Telegram HTML, email HTML and plain text.
- **Telegram bot** (`alerts/bot.rs`, `alerts/control.rs`): one `getUpdates` supervisor (Detect mode for 2 min from the Alerts page; Commands mode when `telegram.listen` is on). Read-only commands `/positions /pnl /algos /status /control /help` for allow-listed chats. **Control buttons** (`telegram.controls`, default off, needs `listen`): arm/disarm, kill / release, resume a halted account, exit one, exit all; shown under `/positions /algos /control` and on risk and algo alerts. Only private allow-listed chats where sender id == chat id; everything except disarm needs a second press (single use, 30 s, same chat and person, in-memory `Prompts`); buttons on messages older than 6 h are refused; actions run through the normal services as `Actor::Telegram` with an audit entry (`telegram_control` / `_failed`). Callback data is capped at 64 bytes (short codes plus ids; `pos_key` hashes a position).
- **Trade copier** (`trading/copier.rs`, table `copy_links`): one master, N children, replicated through `place_inner`; `copier_lock` serialises placement.
- **Signals / algos / backtests**: `charts/rules/` (JSON `vars[]` + `entry`/`exit` trees, pure engine, closed candles only) feeds `algo/` (option algos on one saved signal, runner every 5 s, one capital pool per account, BUY only, `allowLive` needed for Dhan, decisions in `algo_journal`) and `backtest/` (one signal on one instrument over stored bars, fills at next bar open, long only).
- **Market data**: source `nse` | `fyers` (`data.source`); only the selected one is polled. `market/status.rs` market status (08:30-16:00 IST window, `guard_hours`); NSE session in `market_clock.rs`. Fyers: one shared HSM socket (`market/fyers_socket/`), REST seed/fallback, header index seed and login badge. Every Fyers REST call goes through `market/fyers_api` (`get`/`post` + `send(endpoint, Category, Priority, req)`): limiter (plan presets, persisted day counter, 429 pauses), pacing, health indicator, `Kind::Api` alert. New Fyers calls must use it.
- **Charts**: ticks fold into 1m bars (DuckDB `bars`), other intervals resampled on read; Fyers backfill only (never live). Held contracts are always recorded (`Recorder::set_pinned`).
- **Headless** (`headless/`): `kissa --headless` (or `KISSA_HEADLESS=1`), `--control-port` (default 8787), `--no-control`, `--show-control-token`. `kissa.lock` instance lock, `kissa-headless.log`, graceful shutdown (Ctrl-C / SIGTERM / `POST /v1/shutdown`). Feeds run on demand (index feed only while an algo is armed, polling only when something is armed/open). Loopback control API with bearer token: `GET /v1/status|accounts|algos|risk|fyers/login-url`, `POST /v1/algos/{id}/arm|disarm`, `/v1/kill`, `/v1/resume`, `/v1/fyers/login`, `/v1/shutdown`. Linux servers need GTK libs plus a display (Xvfb).
- **UI**: event-driven (events: `quotes`, `bar-update`, `chain-snapshot`, `order-update`, `broker-status`, `index-tick`, `risk-update`, `alert-update`, `copier-update`, `algo-update`, `market-status`); page polls use `lib/timers.ts` `every()`. `KISSA_EMIT_STATS=1` logs emit rates (`emit_stats::count` at new emit sites). Pages can pop out into windows `pop-1`..`pop-8` (`popout.rs`, per-window settings via `getScoped`/`setScoped`).
- **CSP** (`tauri.conf.json`): the webview loads nothing remote and makes no network calls (all in Rust). A feature needing a remote font/image/iframe or frontend `fetch`/`WebSocket` must extend the CSP (prefer Rust).
- **Dashboard / export**: `trading/period.rs` holds fill and round-trip aggregation (`diary_rows` / `trip_row` feed the Dashboard, CSV diary and Orders Round trips view so all count identically; realised P&L belongs to the IST period of the fill, ROI = net / opening balance of the period, see `trading/capital.rs`). `trading/export.rs` builds CSVs (IST, formula-injection prefix `'`, saved through a native dialog from Rust). Backup (`backup.rs`): `VACUUM INTO` plus a locked DuckDB copy into a timestamped folder; keychain secrets are not backed up.
- **broker-proxy contract**: REST + one WSS per client; header `X-API-Key`; `POST /v1/sessions` (`{broker:"dhan",credentials:{clientId,accessToken}}` or `{broker:"paper"}`) returns `sessionId`, then also send `X-Session-Id`. `POST/PUT/DELETE /v1/orders[/{id}]`, `/v1/orders/slicing`, `GET /v1/orders`, `/v1/orders/{id}`, `/v1/orders/external/{correlationId}`, `GET /v1/trades`, `GET /v1/ws?since=N` (`order_update`, `feed_status`, `session`, per-session `seq` with replay and `gap`). Only LIMIT and STOP_LOSS with positive `price`; strict JSON; idempotency via `correlationId` (`409 outcome_unknown` = check `/orders/external/{id}` first). The server persists nothing, so the client is the system of record. One session per Dhan account; a proxy restart drops sessions.

## Known gaps (candidate follow-ups)
- Orders/data: an order left `UNKNOWN` after retries is resolved only by the 60 s resync; `save_account` does not drop a cached Dhan connection; positions are keyed by account + instrument + product (no INTRADAY->MARGIN conversion); special sessions (Muhurat) are not covered; NSE time sync still runs when Fyers is selected; Fyers tokens expire daily (re-login each trading day).
- Algos/backtests: no backtest of a saved algo, no shorting, no saved runs, no stock algos, BUY only; the option feed streams the whole chain of an armed algo's underlying.
- Headless/ops: no UI attach to a running headless instance, no CLI to import secrets or migrate keychain secrets to the file, no backup restore (copy files back with the app closed) or scheduled backups, DuckDB SQL resampling not used (Rust resamples).
- Pop-outs: no dock back, named workspaces or query strings in pop-out routes. Alerts: no plain signal alerts (no orders).
- `ServerConfig::base_url` treats any `http://localhost...` prefix as local (e.g. `http://localhost.evil.com`); not tightened.
