## Objective
Desktop trading app for stock/options: live option prices from NSE public API (default) or Fyers (user's own creds), charts with indicators and rule-based signals, and order placement through the user's `broker-proxy` (static-IP VM) fronting Dhan. **Credentials, order log and account data stay client-side** (secrets in OS keychain, everything else in SQLite).

**Strategy: harden the product with paper trading first.** The user has not set up the VPS, Dhan or Fyers, so nothing real-broker or Fyers is validated. Paper must behave like a real broker so switching later is a small change. For dev without a VPS: run `broker-proxy` locally (localhost is allowed), `proxy keygen`, enter the key under Settings > Server connection (paper orders require it, see Order gate).

Stack: Tauri v2 (Rust) + SvelteKit/Svelte 5 + Tailwind v4 + DaisyUI 5 (themes `kissa-dark`/`kissa-light`, all styling in `src/app.css`), `sqlx` 0.9 SQLite, lightweight-charts.

## What is built
All items below are tested by the user unless noted. Details are kept only where a pending roadmap item or a future change needs them; read the code for the rest.

- **Accounts** (`accounts.rs`): kinds `paper`, `dhan`, `proxy`, `fyers`. Secrets (Dhan/Fyers tokens, app secret) live in the OS keychain; the frontend never receives them. Fyers login (`components/FyersLogin.svelte`): auto (loopback redirect `http://127.0.0.1:<port>/`, default 8765, avoid browser-blocked ports like 5060/5061) or paste of the auth code; token expires daily 6:30 AM. Endpoints are `fyers.auth_url` / `fyers.validate_url`.
- **Option chain**: NSE or Fyers source, live ticks, derived OI change and Black-76 Greeks, configurable columns, click bid/ask/LTP to open the order ticket. NSE chain is empty outside market hours. Per window (`AppState.chain` keyed by window label).
- **Charts**: panels per page; instruments = indices and option strikes streamed on the chain page (ATM +-20) or by the background feed. Ticks fold into 1m bars (`bars` table), other intervals resampled on read, Fyers backfill (never run live). Indicators and auto signals as usual.
- **Signals** (`charts/rules/`, table `rulesets`): JSON `vars[]` + `entry`/`exit` condition trees. The engine is pure (`evaluate`, `conditions`, `decide`) and reused by algos and backtests. Closed candles only; Entry fires when flat, Exit only after an Entry. `/signals` page and a Signals dropdown on chart panels.
- **Orders / trading** (`trading/`): ticket, Orders/Trades/Positions pages, estimated charges (`settings.json` `trading.charges`).
  - Flow (`service/orders.rs`): validate -> server gate -> account/broker -> resolve contract -> `broker.pre_trade` -> insert -> `broker.place` -> `apply_reply`. **Every state change goes through `apply_state`** (books fills via `store::record_fill`); broker pushes arrive as `BrokerEvent` -> `apply_update`.
  - `Broker` trait (`trading/broker/mod.rs`): to add a broker, implement it in a new folder and register it in `TradingService::new`. `BrokerError.unknown` = outcome unknown (order marked UNKNOWN, resynced every 60 s).
  - Paper broker (`broker/paper/`): slippage/latency, simple margin check, day-order expiry, bracket/OCO, expiry settlement, INTRADAY square-off. Dhan via proxy: never run live.
  - Exit / Exit All (`service/exit.rs`): cancels the contract's open orders, then LIMIT at LTP +- `trading.exit_buffer_ticks`.
  - Order gate (`trading/server.rs`): `place`/`modify` need the proxy to authenticate the client; cancel is not gated.
- **Settings page**: server connection (URL, port, API key in keychain) and a `settings.json` editor.
- **Live settings (Roadmap #20 done)** (`settings.rs` `LiveConfig`, `AppState.live`): `AppState.config` is the startup snapshot; `AppState.live.get()` is what applies now. Saving `settings.json` (`save_settings_json`) or the server form calls `live.apply`, which takes over `trading.*` (except `request_timeout_secs`), `risk_free_rate` and `server`. Read live values with `live.get()` at the moment of use (`TradingService::cfg()`, `PaperBroker::cfg()`; do not cache the `Arc` across long waits). Restart-only: `system`, `market_runtime`, `fyers`, `charts`, `trading.request_timeout_secs`; `restart_pending` (command `get_restart_pending`) lists saved sections that differ from the running ones and the Settings page shows them. `risk_free_rate` reaches an open NSE / Fyers chain only when it is reopened (the engine takes the rate at creation); the background Fyers feed reads it on every poll. Edits made to the file outside the app are not picked up until restart.
- **CSP (Roadmap #21 done; user verified)** (`tauri.conf.json` `security.csp` / `devCsp`): the webview loads nothing remote and makes no network calls (Fyers, NSE and the proxy all run in Rust), so production allows only `'self'`, `ipc: http://ipc.localhost` for `connect-src`, `data:`/`blob:` images, `'unsafe-inline'` styles (Svelte inline `style` attributes via `style-src-attr`), no objects, forms or other bases. `devCsp` adds the Vite dev server websocket and inline scripts. Tauri adds hashes for the bundle's inline scripts at build. A new feature that loads a remote font, image, iframe or calls `fetch`/`WebSocket` from the frontend must extend the CSP (prefer doing it in Rust).
- **Risk controls** (`trading/risk.rs`, `service/risk.rs`, tables `risk_limits`, `risk_halts`): per-account limits, daily-loss monitor every 5 s, kill switch (account id `*`). **Orders that only reduce a position always pass**, so Exit, brackets and square-off are never blocked. Algos call `halt_reason(account_id)`. Event `risk-update`.
- **Audit journal** (`audit/`, table `audit_log`, page `/journal`): `audit::record(Entry::new(Category, "action", "summary").account(id).subject(ref).detail(json!{..}))` works from anywhere (global, never blocks or fails; a worker resolves the account name, writes, emits `audit-update`). Actor (`user|system|algo|copier|broker`) comes from the task-local `audit::scope(Actor, fut)`: Tauri order / risk commands run as `User`, the algo runner and copier calls as `Algo` / `Copier`, everything else defaults to `System`; spawned tasks do not inherit it. Order entries live in `trading/service/journal.rs` (placed, place_failed, each fill, cancelled / rejected / expired / unknown, modified, cancel / modify failures, exit_all). Also: risk (halt, limits, kill switch, resume), algo (created / saved / deleted / armed / disarmed / auto-disarm), copier (config, failed, out of step), accounts (saved, deleted, test, Fyers login, broker connect), settings (`data.*` only, settings.json sections, server), system (app start, connection lost / restored, API failing). Never log secrets: callers pass none and `Entry::detail` masks keys containing token / secret / password / apikey (so do not name a detail key like that). Retention 90 days plus a 200k-row cap, pruned at startup and daily. To add an event: call `audit::record` where it happens. `algo_journal` (per-decision log) and `alert_outbox` stay separate.
- **Alerts** (`alerts/`, table `alert_outbox`): `AlertService::notify(Alert{kind,key,title,body})` -> toggle filter -> de-dup per `kind:key` -> Telegram / SMTP delivery with retries -> history. To add an event: add a `Kind` variant (and to `Kind::EVENTS`), then call `notify`. Token expiry reminders are estimates (saved time + `fyersTokenHours`/`dhanTokenHours`). Not done: plain signal alerts (no orders), a "Detect chat ID" button.
- **Trade copier** (`trading/copier.rs`, `service/copier.rs`, table `copy_links`): one master, N children, replicated on placement through `place_inner`. `copier_lock` serialises `place`, follow tasks and exits. Child accounts should be used only for copying. Event `copier-update`.
- **Algo trading** (`algo/`, tables `algos`, `algo_state`, `algo_journal`): option algos on one saved signal; each CE/PE leg is judged on its own option bars; runner every 5 s; one capital pool per account; paper brackets or runner-watched SL/target for Dhan; `allowLive` needed for Dhan. Every decision goes to `algo_journal` (5000 rows / 60 days) and key events go out as `Kind::Algo` alerts. Needs the app running; BUY only; no stock algos. Option bars come from `trading/feed.rs` `Recording` (no live backfill). JSON share format `{kissaAlgo:1, algo, signal}`. Event `algo-update`.
- **Backtesting** (`backtest/mod.rs`, command `run_backtest`): one saved signal on one instrument over stored bars; fills at the next bar's open; long only. Not done: backtesting a saved algo, shorting, saved runs.
- **Dashboard** (`routes/+page.svelte`, `trading/period.rs`, command `get_performance`): Daily / Monthly / Yearly views, calendar heat map, diary. Each fill's realised P&L and charges belong to the IST hour/day/month of the fill; a trade = round trip (counts when it closes); ROI = net / entry premium; open positions are not included. `period.rs` is where trade / fill aggregation lives; `diary_rows` / `trip_row` give the flat round-trip list used by the CSV diary export and the Orders page Round trips view (so all three count identically).
- **CSV export (Roadmap #19 done)** (`trading/export.rs`, command `export_csv`, `components/ExportCsv.svelte`): one dialog (button on the Orders page and the Dashboard) with dataset **Orders / Trades / Trader's diary**, IST From-To range (presets) and account. `export::render` loads with `store::orders_between` / `trades_between` (no row cap, unlike `list_orders` / `list_trades`) or, for the diary, `trades_for_window` + `period::diary_rows` (one row per round trip, dated on the day it closed, Open/Closed status). Times are IST; text from outside the app (account names, broker ids / messages) gets a leading `'` when it starts with `= + - @` (formula injection), numbers are never touched. The command shows the native save dialog from Rust (`tauri-plugin-dialog`, parented to the calling window, so it works in pop-outs; no npm package or capability needed), appends `.csv` if missing, writes the file and records an audit entry (`System` / `csv_export`). An empty range saves nothing and says so; cancelling the dialog is silent.
- **Orders page Trades tab: Fills | Round trips (default Round trips)**: `Fills` = one row per execution (`list_trades`, capped at 2000); `Round trips` = entry + exit as one row (`list_round_trips` -> `DatedTrip`, newest first, listed on the closing day; open trades show their entry only). The tab count follows the selected view, and the Export dialog defaults to `diary` for Round trips and `trades` for Fills. A fills count is never lower than the filled-orders count; "trade = round trip" is the Dashboard definition.
- **Top bar P&L and positions dock**: `components/TopBarPnl.svelte` (net today across accounts, same maths as the Dashboard) and `components/PositionsDock.svelte` (Option Chain and Charts). Both use `getDashboard(null)` + `livePosition` and refetch on `trading.version`. Held contracts are always recorded as bars (`Recorder::set_pinned`).
- **Multiple app windows** (`popout.rs`, `lib/windowing.ts`): any page can open in its own window (`pop-1`..`pop-8`), one process and backend, per-window JS stores fed by the same events. `isPopout` hides the sidebar. Per-window settings use `getScoped`/`setScoped` (`key@pop-N`); `data.source` and `ui.theme` are global. Open pop-outs are saved in `windows.open` and restored. `capabilities/default.json` covers `main` and `pop-*`; pop-outs load the same bundle, so they share the CSP. Not done: dock back, named workspaces, query strings in pop-out routes.
- **Event-driven UI**: no timers wake the backend while the market is quiet. `LtpStore::set` notifies the `quotes` emitter (50 ms coalesce); `index-tick`, `bar-update` coalesce the same way. Frontend: `lib/timers.ts` `every(fn, ms)` skips while `document.hidden`; use it for page polls. Events: `quotes`, `bar-update`, `chain-snapshot`, `order-update`, `broker-status`, `index-tick`, `risk-update`, `alert-update`, `copier-update`, `algo-update`, `market-status`. `KISSA_EMIT_STATS=1` logs emits per second (`emit_stats::count("event")` at emit sites; add it to new emitters). The chain engine still ticks every 150 ms while a chain is open.
- **Fyers data socket** (`market/fyers_socket/`): one shared HSM binary socket (`fyers.socket_url`) for the Fyers chain, the background feed and the header indices (`bridge.rs`, same `IndexSink` as the NSE stream, NSE index names). Consumers take a `Lease` and read `hub.subscribe()`. The supervisor connects only while the data source is Fyers, a lease wants topics, and the Fyers status allows polling. REST chain call seeds the chain and refreshes every `fyers.chain_refresh_secs`; if the socket is down 20 s the chain falls back to REST. `fyers.use_socket = false` keeps REST only. Settings: `use_socket`, `socket_url`, `symbol_token_url`, `max_symbols` (100 Standard / 5000 Prime), `chain_refresh_secs`. `proto.rs` (pure, tested) and `topics.rs` (index topics from the SDK `map.json` names). `KISSA_FYERS_DEBUG=1` logs frame bytes. Hub accessors `is_connected`, `last_error`, `last_tick_age_secs` feed the header indicator. **Unverified against live Fyers:** the symbol-token `Authorization` format, exact index topic names, the auth `source` string ("kissa"), whether chain items carry `fyToken`, ack and ping behaviour.
- **Fyers header index seed and login indicator (Roadmap #15 done; tested by the user)**: with Fyers selected and the socket down (market closed), `fyers_socket/bridge.rs` `maybe_seed` fills the header once: one REST quotes call (`chain/fyers.rs` `fetch_quotes` / pure `parse_quotes`, setting `fyers.quotes_url`) mapped to `IndexTick` (`mkt_status` Open/Closed from the Fyers status). It runs when Fyers becomes the source and again each time the socket drops; skipped while the socket is connected. Failures are silent (retry after 60 s). Seeded ticks go through the normal `IndexSink`, so they also write a 1m bar per index at the current time.
  - **Token state**: `accounts::fyers_auth` (cached 10 s, cleared on login) classifies the data account as `ok` / `expired` (JWT `exp` passed) / `missing` / `noAccount`; it rides on `MarketStatus.fyersAuth` (set only while Fyers is the source, part of `change_key`). The header shows a red "Fyers login expired / not logged in · Log in" badge (amber "select account" link for `noAccount`); click opens `FyersLogin` in a modal inside `+layout.svelte` (works in pop-outs).
  - **After login**: command `fyers_login_finished` runs the account test (option-chain fetch); if it passes it calls `Hub::token_renewed()`, which re-seeds the header and cuts short a socket back-off. A failed test shows the reason in the layout error banner.
  - **NSE fallback**: when the token is expired/missing (or the Fyers quotes call fails) and the header has no prices, the NSE index stream is polled up to 3 times (`indices::poll_once`, now `pub(crate)`) to seed it; with an unusable login the NSE prices stay until the next login re-seeds from Fyers. NSE is used for nothing else while Fyers is selected.
  - A token Fyers rejected before its `exp` is now handled (see the rate limiting entry).
- **Market status and data source (Roadmap #14 done; tested by the user)**: only the selected source is polled, streamed and shown.
  - `DataSource` (`nse` | `fyers`, setting `data.source`) is cached in `MarketStatusService`: loaded at startup, updated by the `set_setting` command (`set_source`). Read it with `state.market_status.source()` instead of the database. The unselected source reads `Reason::NotUsed` and makes no calls; a newly selected source gets a fresh poll at once. `trading/feed.rs` restarts its feeds when the source changes and never falls back to NSE when Fyers is selected.
  - `market/status.rs` polls NSE `/api/marketStatus` (Capital Market row; F&O follows) or Fyers `/data/marketStatus` (NSE 10, derivatives 11, NORMAL row). No calls outside the weekday 08:30-16:00 IST window; every 5 min while stable, 30 s around pre-open (08:55-09:20) and the close, none after the day's close. `guard_hours`: before 09:00 a reported Open/Pre-open shows as Closed, and 09:00-09:15 Open shows as Pre-open (the raw source text stays in the badge tooltip).
  - `SessionState` (`market_clock.rs`) is the **NSE** session only and is always Idle when Fyers is selected (`nse_enabled`): indices stream through pre-open, option streams only when Open, nothing connects while Closed (the NSE index stream makes up to 3 price-seed polls), unknown status falls back to the clock rules, streams that connect without a tick back off to 5 min. The Fyers chain page, price feed and socket use the Fyers status directly (one REST fetch when closed).
  - Header (`+layout.svelte`): one badge for the selected source (`MarketStatus.exchange`) and a feed indicator (`live`, `feed`, `feedDetail` from `commands::build_market_status`). Live = the selected source's index feed (NSE `indices` stream or Fyers socket) delivered a tick within 60 s while the exchange is Open (with an unknown status the clock decides, 09:15-15:30 weekdays); otherwise Pre-open, Closed, No ticks, Connecting, Error or Checking. The push task emits only when `change_key` changes (exchange state, source, live, feed text, stream state; tick counters and clock are ignored). `market.svelte.ts` keeps the IST clock running locally from `nowMs`.
  - Known gaps: pre-open status strings for NSE and Fyers segment 11 are unverified; special sessions outside 08:30-16:00 (Muhurat) are not covered; NSE's server-time sync (`refresh_if_stale`, one small GET per 15 min) still runs when Fyers is selected. The NSE holiday-master code and the `system.holidays` setting were removed in #22 (unused; see git history if a "next trading day" feature needs them).

- **Fyers rate limiting and API health (Roadmap #16 done; tested by the user)** (`market/fyers_api/`: `mod.rs` wrapper, `limiter.rs`, `health.rs`).
  - **One wrapper**: every Fyers REST call is built with `fyers_api::get` / `post` / `post_anonymous` and sent with `fyers_api::send(endpoint, Category, Priority, req)` (`send_with(.., judge_auth)` for the login exchange). No call site uses `reqwest` for Fyers directly; new Fyers calls (orders, funds, ...) must do the same. `FyersApi { limiter, health }` is in `AppState.fyers_api` and also installed as a process global (`fyers_api::install` / `global()`), so deep call sites need no extra argument. Without it (unit tests) calls go out unthrottled. `Reply { status, body }` is returned; Fyers' own `"s":"error"` replies are not API failures and reach the caller to parse.
  - **Limits** (`settings.rs` `FyersLimits`): `fyers.plan` (`standard` | `prime`) picks a preset, `fyers.limits` (default `null`) overrides it. Fields: `data` / `account` per-sec/min/day, `headroom` (0.8), `quotes_per_request` (50 / 1000), `history_daily_days` / `history_intraday_days` (1825 / 365, 0 = no clamp), `max_symbols`. `FyersConfig::max_symbols_eff()` uses the plan's value unless `max_symbols` was changed from 100. Category `Data` = chain, quotes, history, symbol-token, market status; `Account` = login exchange (and future orders / funds).
  - **Limiter**: sliding second/minute windows in memory; day counter, breaches and the day pause persisted in table `fyers_usage` (IST date, flushed every 5 s). `Priority::User` may use the whole budget and waits up to 30 s; `Background` uses 75 % of the minute and 85 % of the day budget, waits up to 5 s, then fails with `Throttled` (callers treat it as a failed call and retry later).
  - **Pacing**: `fyers_api::paced(Category::Data, base)` stretches a poll interval so the rest of the day's background budget lasts until the 15:30 close, shared by the registered polling loops (`fyers_api::poller()` guard, held only while a loop polls over REST). Used by the REST loops and the socket-mode chain refresh in `chain/runner.rs` and `trading/feed.rs`.
  - **429 handling**: HTTP 429 or code `-429` pauses the category. First per-minute breach of a day pauses 5 min, second 30 min, third the rest of the day; concurrent 429s of one incident count once; `Retry-After` of 2 s or less is a burst, not a breach.
  - **Chain sharing**: `chain::fyers::fetch(.., prio)` shares one request per (app id, symbol, strikes, expiry) for 1 s (`fyers_api::shared`); only valid chains are kept.
  - **History / quotes**: `backfill::clamp_days` limits ranges to the plan; `fetch_quotes` batches by `quotes_per_request`. Expired F&O intraday and screener endpoints are never called.
  - **Usage UI**: command `fyers_usage`, card on the Settings page (used / budget per second, minute, day, paused state, hints when `use_socket` is off or polling is stretched).
  - **ApiHealth** (`health.rs`): per (source, endpoint) last success, consecutive failures, kind (`Auth`, `RateLimited`, `Server`, `Network`), message, `Retry-After`. An endpoint is failing after 3 in a row, or at once for `RateLimited` / `Auth`; the next success clears it; failures older than 15 min are ignored. Fed by the Fyers wrapper and by NSE `marketStatus` and the NSE index / option stream connects (`fyers_api::nse_ok` / `nse_fail`). Exposed as `MarketStatus.apiHealth` (in `change_key`); `build_market_status` replaces the feed label with amber "API error" / "Rate limited" (tooltip: endpoint, message, since when). Cleared on a new Fyers login and when `data.fyers_account` changes. `Kind::Api` alert (de-duplicated per endpoint) fires when an endpoint turns bad.
  - **Rejected token**: an `Auth` outcome calls `accounts::mark_fyers_rejected()`; `fyers_auth` then reports `expired` (header Log in badge) and Background calls are refused until a User call succeeds or a login completes (`clear_fyers_rejected`). The login exchange uses `judge_auth = false`, so a wrong auth code does not count.
  - **Unverified against live Fyers**: the auth error codes (`-8`, `-15`, `-16`, `-17`), which endpoints Fyers counts as Data vs Transaction + User Info, whether 429s carry `Retry-After`, and the day reset moment (assumed IST midnight).

**23. Replace SQLite with DuckDB.** Better performance and a better fit for backtests and analytical queries over `bars`, `trades` and the journals. Things to settle before coding (review the design with the user first):
- Driver: `sqlx` has no DuckDB backend, so every `sqlx::query*` call site (`db.rs`, `store.rs` files, `audit/`, `alerts/`, `algo/`, `charts/`, `fyers_api` usage table) moves to the `duckdb` crate behind one small data-access layer; decide whether that layer is async (worker thread / `spawn_blocking`) and keep the `AssertSqlSafe` discipline of parameterised SQL.
- Workload split: DuckDB is columnar and weak at many small concurrent writes. The live paths (tick -> 1m bar flush, order / fill inserts, audit, `algo_journal`, `fyers_usage`) are small, frequent writes from several tasks; check single-writer behaviour, and consider keeping a small transactional store for orders / accounts / settings and DuckDB for bars and analytics instead of a full replacement (an option to put to the user).
- Migration: one-off import of an existing `kissa.db` (all tables, including the `*_legacy_*` ones) with a backup first; the database backup button (#24) must then copy the DuckDB file (and its WAL), so #24 is done after this item so it targets the final engine.
- Re-check SQL that is SQLite-specific (`rowid`, `INSERT OR REPLACE`, `PRAGMA`, `VACUUM INTO`, `AUTOINCREMENT`, type affinity for REAL / INTEGER / TEXT dates).
- Payoff to build alongside: backtests (`backtest/mod.rs`) and the diary / dashboard aggregations could run as SQL over bars and trades instead of loading rows into Rust.

**24. Database backup button (after #23, so it targets the final engine).** Settings page: copy the SQLite file (consistent snapshot, e.g. `VACUUM INTO`) to a chosen folder. Secrets live in the OS keychain and are not part of the backup; say so in the UI.

**25. Headless mode.** Run the app without a window, on a server or as a background process on the local machine, with armed algos working and every feed the algos and orders do not need switched off to save API cost:
- Entry point: a `--headless` flag / separate binary that builds the same `AppState` and services (trading, algo runner, risk, alerts, copier, audit) without creating a window; the UI is just a client of these services today, so the split is mostly in `lib.rs` setup. Needs a clean shutdown, a lock so two instances never share one database, and logs to a file.
- Feeds on demand: gate the NSE index stream, header seeds, market-status polling, chain engines and chart recorder behind "is anything consuming this". In headless mode only the contracts of armed algos, open positions and pending orders are subscribed (`trading/feed.rs`, `Recorder::set_pinned`, Fyers socket `Lease`s); no index ticker, no chain, no REST polling beyond what the algo signals need. Keep the Fyers limiter, market-status guard and the 5 s algo runner behaviour unchanged.
- Credentials: the OS keychain may not exist on a server (no Secret Service); decide an alternative (env vars, an encrypted file with a passphrase) and keep the "secrets never in SQLite / settings.json" rule. Fyers tokens expire daily at 6:30 AM, so a headless run needs a re-login path (Telegram prompt, #26, or a login URL on a local-only HTTP endpoint).
