## Objective
Desktop trading app for stock/options: live option prices from NSE public API (default) or Fyers (user's own creds), charts with indicators and rule-based signals, and order placement through the user's `broker-proxy` (static-IP VM) fronting Dhan. **Credentials, order log and account data stay client-side** (secrets in OS keychain, everything else in SQLite).

**Strategy: harden the product with paper trading first.** The user has not set up the VPS, Dhan or Fyers, so nothing real-broker or Fyers is validated. Paper must behave like a real broker so switching later is a small change. For dev without a VPS: run `broker-proxy` locally (localhost is allowed), `proxy keygen`, enter the key under Settings > Server connection (paper orders require it, see Order gate).

Stack: Tauri v2 (Rust) + SvelteKit/Svelte 5 + Tailwind v4 + DaisyUI 5 (themes `kissa-dark`/`kissa-light`, all styling in `src/app.css`), `sqlx` 0.9 SQLite, lightweight-charts.

- **Trade copier (Roadmap #4 done; tested by the user)**: `/copier` page (master, children with factor / rounding / min 1 lot / on-off, recent copies).
  - One master account, N children (paper or Dhan). Config JSON in `app_settings` key `copier.config`; links in table `copy_links` (master order -> child order, lots, status `placed|skipped|failed`, message).
  - **Replicate on placement** (user's choice, not on fill): `TradingService::place` = `copy_job` (reads config and the master's position *before* the order: intent Open / Reduce / full exit) -> `place_inner` (the old `place` body) -> `spawn_copy` unless the master order was REJECTED (UNKNOWN still copies). Children are placed through `place_inner`, so server gate, risk checks and broker rules apply and a copy is never re-copied. Children run concurrently in a background task.
  - **Scaling** (`copier::plan_lots`, pure, unit-tested): child lots = master lots x factor, Down/Nearest/Up, below 1 lot -> 1 if `minOneLot` else skipped. Orders that only reduce the master are capped at what the child holds (never opens a position the master did not); a full master exit closes the child's whole position and first cancels the child's open orders in that contract (like Exit does).
  - **Follow** (`copier_follow`, hooked in `after_state`): master order CANCELLED/EXPIRED/REJECTED -> unfilled child orders cancelled; master price/trigger changed while open -> child orders modified (not if the child is part-filled). Roles other than plain/ENTRY (stop/target legs, settlement) are ignored.
  - **Failures**: one child failing never stops the others; recorded in `copy_links` and alerted with `Kind::Copier` (a child order REJECTED by the broker only gets the existing Rejection alert).
  - **Concurrency**: `copier_lock` (`Arc<Mutex>`) is taken by `place` (owned guard) from before the master order until its copies are placed, and by follow tasks. `exit_one` waits on it and re-reads the live position, so Exit all on master + children cannot exit a child twice (this happened before the fix).
  - **Paper funds fix**: orders that only close exposure (requirement 0) always pass `check_funds`, even when the account is over-committed.
  - Not copied: the master's stop-loss/target legs and expiry settlement. A paper child gets the master's bracket on its own entry copy; a Dhan child does not (link note says so). Child accounts should be used only for copying: a full exit on the master closes the child's whole position in that contract, including anything the child traded itself. Exit / square-off / kill-switch flatten on the master are copied too (children already flat just skip).
  - Code: `trading/copier.rs` (config, scaling, links), `trading/service/copier.rs` (wiring); commands `get_copier, save_copier`; event `copier-update`. Frontend `routes/copier`, `trading.copierVersion`.
- **Algo trading (Roadmap #5 done; tested by the user)**: `/algos` page (form editor or JSON view on the left; Status, open legs and decision journal on the right; Arm/Disarm).
  - **Model** (`algo/mod.rs`, JSON in SQLite `algos`, `ruleset_id` column): `signalId` (one saved signal; a signal has many algos), `instrument {type:"option", underlying, expiry: current|next|next1|next2|next3, strikeOffset (ATM = 0, +n above, -n below, max 20), side: ce|pe|both}`, `interval` (minutes, e.g. `5m`), `action {product, capital, bufferTicks, stopLossPct, targetPct}`, `accounts[]` (many algos <-> many accounts), `copier` (algo-level switch), `allowLive`. Names are unique. Only options are supported: `type` is kept so stocks can be added later (the UI shows Stock disabled).
  - **Signal link**: signals are loaded by id on every evaluation, so editing a signal changes every algo using it. `rules::store::delete` refuses while an algo uses the signal (lists the algo names).
  - **Run loop** (`algo/runner.rs`, every 5 s, armed algos plus disarmed ones still holding a leg): **each option leg is judged on its own bars** (per-leg signals, changed after Roadmap #5 first shipped, which evaluated the underlying and opened both legs together). Once per newly closed bar (`last_closed_bucket`, session-aligned like stored bars; the first look after arming only records the baseline bucket), for each leg in the order CE then PE: a **held** leg cancels its unfilled entry and checks Exit on its own option bars (`eval::decide(.., in_pos = true)`), also for a leg whose side was removed from the algo later; a **flat** leg (armed only, side selected) takes the underlying's last closed bar close as spot, strike = ATM +- offset (`target_strike`), and checks Entry on that strike's bars. A leg's strike is fixed until that leg closes. `ce`/`pe` watch one leg, `both` watches both independently (a PE signal can come while the CE is open). A bar counts only if it exists for the closed bucket (no trades = no bar = no signal), and the option needs `warmup_bars(rs)` closed bars (sum of variable lookbacks + 2; journaled once as 'waiting for history'). Entry: BUY LIMIT at LTP + `bufferTicks`; unfilled entry orders are cancelled at the next bar. `sync_legs` drops legs whose position is closed (state in `algo_state`, targeted UPDATEs); the algo is flat when no leg is left.
  - **Capital is one pool per account** (no split between legs; `Leg.cost` = entry price x lot size x lots): lots = `floor(free / one-lot cost)` with `free = capital - sum(cost of that account's open legs)` (`free_capital`). The first leg to signal can use everything; a later leg with less than one lot free is journaled `Insufficient funds on <account>: ...` and skipped. Legs saved before this change have `cost` 0.
  - **Option bar recording** (needed for per-leg signals): the Option Chain page recorded ATM +- `charts.persist_strikes_each_side` only while open; `trading/feed.rs` (`Recording`) now records the same window for every target the background feed streams (armed algos publish theirs via `set_algo_watch`), NSE and Fyers. No live backfill: a new strike/expiry needs about `warmup_bars` x interval of recording before it can signal; arm before the open for best results. A strike that was never inside the window has no bars.
  - **Stop-loss / target**: paper accounts get bracket orders (`PlaceOrderInput.bracket`); Dhan accounts have the runner watch the price (needs the app running).
  - **Accounts and copier** (`algo::select_accounts`, pure, unit-tested): algo copier ON + copier set-up enabled + its master selected in the algo -> only the master places orders (copier replicates to its active children) and selected children are ignored (journaled). Otherwise every selected account places its own orders. Algo copier OFF -> orders are never replicated, even from a master: `TradingService::place_algo(input, propagate)` uses `place_inner` (no `spawn_copy`) and `algo_close` / `exit_one_with(.., propagate)` do the same for exits.
  - **Safety**: arming needs a valid signal, at least one account, `halt_reason` clear, and `allowLive` for any Dhan account (confirm dialog). The runner disarms on the kill switch or a daily-loss halt (alert + journal). Orders go through the normal flow, so the server gate and `check_risk` apply. `allowLive` is never exported.
  - **Prices / expiries**: entries need a live option price (age <= 120 s). The runner publishes the (symbol, expiry) pairs it needs through `TradingService::set_algo_watch`, merged into `watched_contracts()`, so the feed prices them. Expiries come from the Dhan `scrip` table, topped up from NSE `fetch_expiries` (cached per IST day). Strike steps (`strike_step`: 50 NIFTY/FINNIFTY, 100 BANKNIFTY/NIFTYNXT50, 25 MIDCPNIFTY) are estimates, verify.
  - **Journal and alerts**: every decision goes to `algo_journal` (kept 5000 rows / 60 days; kinds armed, disarmed, signal, entry, exit, skip, error, info). Entries, exits, failures and auto-disarm also go out as `Kind::Algo` alerts.
  - **JSON share**: `{kissaAlgo:1, algo:{name, instrument, interval, action, copier}, signal:{name, vars, entry, exit}}`. No accounts, ids or `allowLive`. On import, a signal with the same name is reused (you are told if its rules differ); an unknown one is created on save.
  - Limitations: the app must stay running (no headless mode); no stock algos; BUY only (no option writing); one signal per algo, one position per leg (CE, PE).
  - Code: `algo/{mod.rs (model, validation, pure maths + tests), store.rs, service.rs, runner.rs}`, `trading/service/algo.rs`; commands `list_algos, save_algo, delete_algo, set_algo_armed, validate_algo, list_algo_journal, clear_algo_journal`; event `algo-update`. Frontend `routes/algos`, `components/AlgoEditor.svelte`, `trading.algoVersion`.
